# Система корпоративного управління проєктами

![Схема бази даних](./Корпоративне%20управління%20проєктами.png)

## Предметна область

База даних призначена для обліку та управління проєктами в компанії. Основні можливості моделі:
- ведення довідників відділів (`departments`), працівників (`employees`), клієнтів (`clients`), ролей (`project_roles`), статусів (`project_statuses`, `task_statuses`), пріоритетів (`priorities`) та міток (`tags`);
- управління проєктами (`projects`), формування команд проєктів (`project_members`) і контрольних етапів (`milestones`);
- розподіл завдань (`tasks`) виключно між учасниками команди відповідного проєкту, класифікація завдань мітками (`task_tags`);
- ведення обговорень у коментарях (`comments`) та облік витраченого часу (`time_entries`);
- підтримка м'якого видалення (**Soft Delete** через `is_deleted`) та автоматичного аудиту змін (`updated_at`, `updated_by`) для проєктів, завдань і коментарів.

## Структура бази даних (PostgreSQL)

Схема нормалізована до **3НФ** і містить **15 сутностей**:

| Сутність | Призначення |
|---|---|
| `departments` | Відділи компанії |
| `employees` | Працівники компанії |
| `clients` | Клієнти (замовники проєктів) |
| `project_statuses` | Довідник статусів проєктів |
| `project_roles` | Довідник ролей у проєкті |
| `projects` | Проєкти (підтримує `Soft Delete` та аудит змін) |
| `project_members` | Учасники проєкту та їхні ролі (`M:N`) |
| `milestones` | Етапи (віхи) проєкту |
| `task_statuses` | Довідник статусів завдань |
| `priorities` | Довідник пріоритетів завдань |
| `tasks` | Завдання проєкту (підтримує `Soft Delete` та аудит змін) |
| `comments` | Коментарі до завдань (підтримує `Soft Delete` та аудит змін) |
| `time_entries` | Записи про витрачений час працівників |
| `tags` | Довідник міток (тегів) |
| `task_tags` | Зв'язок завдань із мітками (`M:N`) |

### Індекси, процедури, функції, тригери та View

У файлі `database.sql` реалізовано:
- **Індекси:** складений частковий B-tree індекс `ix_tasks_project_due` (`WHERE NOT is_deleted`) та Hash-індекс `ix_clients_name_hash`.
- **Функції (4):** визначення поточного користувача сесії (`fn_actor`), розрахунок відсотка виконання проєкту (`fn_project_progress`), тригерні функції аудиту та перевірки активного батьківського запису.
- **Тригери (9):** автоматичне оновлення `updated_at` / `updated_by` та блокування змін у дочірніх записах видалених сутностей.
- **Розрізи даних / Views (7):** `v_projects`, `v_tasks`, `v_comments`, `v_project_members`, `v_time_entries`, `v_employees`, `v_clients` (автоматично приховують записи з `is_deleted = true`).
- **Збережені процедури (15):** операції створення, редагування, логування часу, `Soft Delete` та відновлення (`Restore`).

## Робота з БД із коду

У файлі `main.py` реалізовано патерни **Repository** (`ProjectRepository`, `TaskRepository`, `CommentRepository`, `TimeEntryRepository`) та **Unit of Work** (`UnitOfWork`):
- усі операції читання виконуються через розрізи даних (`v_*`);
- усі операції модифікації виконуються через збережені процедури (`sp_*`);
- `UnitOfWork` забезпечує атомарність транзакції (`COMMIT` при успішному виконанні блоку або повний `ROLLBACK` при помилці).

## Запуск

1. Запустити контейнер із PostgreSQL (скрипт `database.sql` виконається автоматично при ініціалізації):
   ```bash
   docker compose up -d
   ```

2. Встановити залежності та запустити демонстраційний скрипт:
   ```bash
   pip install -r requirements.txt
   export DATABASE_URL="postgresql://postgres:password@localhost:5432/corporate_pm"
   python main.py
   ```
